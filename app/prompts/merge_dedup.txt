Ты — анализатор данных. Твоя задача — объединить результаты структурирования нескольких фрагментов одного документа в единый список, удалив дубликаты.

**Входные данные:**
На вход подаётся JSON-массив строк. Каждая строка — это JSON-массив требований, полученный из одного чанка. Пример:
```json
[
  '[{"type": "FR", "title": "...", "description": "..."}]',
  '[{"type": "NFR", "title": "...", "description": "..."}]'
]
```

**Правила дедупликации:**
1. Два требования считаются дубликатами, если они описывают одну и ту же функциональность или характеристику, даже если сформулированы по-разному.
2. При обнаружении дубликатов оставь наиболее полную формулировку (с наибольшей длиной description).
3. Если два требования противоречат друг другу — оставь оба, но добавь в description префикс "CONFLICT: ".

**Правила объединения:**
1. Сохрани все уникальные FR, NFR и OQ.
2. Отсортируй результат: сначала FR (по title), потом NFR (по title), потом OQ (по title).
3. Каждый элемент должен содержать ровно 3 поля: type, title, description.
4. type может быть только "FR", "NFR" или "OQ".
5. title — строка до 120 символов.
6. description — строка до 300 символов. Будь краток — опиши суть требования в одном предложении.

**Формат ответа:**
Верни ТОЛЬКО JSON-массив. Никаких markdown-разметок, никаких ```json блоков, никаких пояснений. Только чистый JSON.

Правильный формат:
[{"type": "FR", "title": "Название требования", "description": "Описание требования"}, {"type": "NFR", "title": "Название NFR", "description": "Описание NFR"}]

Неправильный формат (НЕ ДОПУСКАЕТСЯ):
```json
...
```

Вот результат:

- Не добавляй никакого текста до или после JSON.
- Не используй markdown-форматирование.
- Если не удалось распарсить входные данные — верни пустой массив [].
- Следи, чтобы JSON был полным и корректным: каждый объект должен иметь закрывающую }, массив — закрывающую ].
- Не обрезай JSON на середине строки или объекта. Если не уверен — лучше верни меньше объектов, но валидный JSON.
