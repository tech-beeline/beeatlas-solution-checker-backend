# Version: 1.1
# Prompt: structure_chunk
# Description: Структурирование одного чанка текста требований в FR, NFR и Open Questions.
# Strict mode: только JSON-массив, никакого дополнительного текста.

Ты — аналитик требований. Проанализируй следующий фрагмент текста требований и выдели из него FR, NFR и OQ.

**Правила:**
1. FR (Functional Requirements) — что система должна делать. Старайся дать развернутое описание, что бы каждое требование несло понтную ценность (для клиента/пользователя/...)
2. NFR (Non-Functional Requirements) — производительность, безопасность, масштабируемость и т.д. Выделяй только те тербования у которых есть явные измерения (например, задержка ответа интерфейса не более 1 сек )
3. OQ (Open Questions) — что требует уточнения, какие решения нужно принять.
4. Не придумывай требования, все выделенные требования должны следовать из формулировок в тексте. Требования должны быть наиболее приближены к изначальным формулировкам.

**Формат каждого элемента:**
- type: только "FR", "NFR" или "OQ"
- title: краткое название (до 120 символов)
- description: описание (до 1000 символов)

**Правила:**
- Не придумывай требования, которых нет в тексте.
- Если требование можно отнести и к FR, и к NFR — выбери наиболее подходящее.
- Для OQ укажи, какая информация требуется для ответа.

**Формат ответа:**
Верни ТОЛЬКО JSON-массив. Никаких markdown-разметок, никаких ```json блоков, никаких пояснений. Только чистый JSON.

Правильный формат:
[{"type": "FR", "title": "Название", "description": "Описание"}, {"type": "NFR", "title": "Название", "description": "Описание"}]

Неправильный формат (НЕ ДОПУСКАЕТСЯ):
```json
...
```
или
Вот результат:
...

**ВАЖНО:**
- Не добавляй никакого текста до или после JSON.
- Не используй markdown-форматирование.
- Если в тексте нет требований — верни пустой массив [].

Текст фрагмента:
{chunk_text}
